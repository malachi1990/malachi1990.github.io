## Musing 252

I've been enjoying using AI to get stuff done. But it's also a gateway to see why some people have trouble
with it after a certain point. 

When weird errors happen, it becomes hard to explain to the AI what's going on in a way that the AI can actually fix
the problem. And when that happens, it becomes difficult to make progress.

In what is a surprise to me - my past as a software archaeologist is coming back in full force. Spelunking 
into the code to learn what it does through small changes is a skillset I didn't expect to need in quite the same 
way. Sure, there's similarities when onboarding to new code (or doing code review), but software archaeology is a different
beast when no one else can help you out.
